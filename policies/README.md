# Policy Store

Authoritative university rules as reviewable, versioned records. Git is the source
of truth; the runtime compiles an artefact from the approved subset. Nothing here is
generated at request time and nothing here is retrieved by embedding similarity —
records are addressed by `topic` and resolved by `authority_level`.

## Why files and not a database table

`verification.status` is a code-review concept. Files give diffs, blame, PR approval
and rollback for free; a table gives none of that, and the approval trail is the
entire point of this subsystem.

## Three layers, and which one you may cite

| Layer | What it is | Citable as source text? |
|---|---|---|
| `evidence/page_text/` | the PDF's own text layer, one file per page, machine-extracted with no model involved | **Yes** — the only verbatim artefact here |
| `<topic>/*.yaml` (81 rule records) | composed rules with conditions, `required_inputs`, `runtime_use` | Their `source_text_ar` is a human/model transcription — checked against the text layer by `tools/check_excerpts.py`, but not authoritative |
| `evidence/knowledge_records.yaml` (277) | a second independent extraction, atomic assertions | **No.** Its `restatement_ar` is a paraphrase (`is_verbatim: false`) — identical to the record's own `statement_ar` in 273/277 |

This ordering exists because both LLM extractions of this guide were caught
paraphrasing while claiming to quote. The rule layer silently repaired the source's
own typo (`المدة الازمة` → `اللازمة`), dropped words (`الرئيس`, `تقديم`,
`دراسيين`), and invented a lower bound (`percent_min: 0` for a band the page states
only as "أقل من 60"). The evidence layer normalised away every Arabic-Indic
numeral and left its excerpt field stale in the four records its own audit
corrected. Neither is a quotation. `page_text/` is.

**`source_text_ar` is not present on all 81 records.** Eleven are `lookup_table`,
`comparison`, `definitions` or `enumeration` shapes whose content is two-dimensional
and has no single quotable sentence. They are marked `STRUCTURE_ONLY` in
`evidence_map.yaml` and must be verified against the rendered page, not against text.

## The calendar layer

`calendar/calendar_1448_t1.yaml` holds 37 dated events for **الفصل الدراسي الأول
1448هـ only**, extracted by `tools/extract_calendar.py` from a hash-pinned capture
of the university's live page. It is what turns the guide's relative offsets
("قبل بدء الدراسة بأسبوع", "منتصف الفصل السابق") into dates.

Five rules now carry a `calendar_binding` and moved from `PROHIBITED_FOR_DECISION`
to `PARTIALLY_EVALUABLE`. Every binding records `covers_term_only`, because **Hijri
dates move every year — a date from one term must never be reused for another.**

Both calendars are kept as printed and neither is computed from the other; a
converted date can land a day off and silently move a deadline.

This is also where `authority_precedence` first decided something. The guide says
registration closes a week before teaching starts; the calendar puts add/drop at
20–22 August with teaching from 23 August. `OFFICIAL_ACADEMIC_CALENDAR` outranks
`OFFICIAL_STUDENT_GUIDE`, so the calendar governs — recorded as
`CONFLICT.ADD_DROP_DEADLINE` in `sources.yaml` with **both readings left intact**.
Neither record was edited to agree with the other.

## Two extractions, deliberately kept apart

The evidence layer is a *second, independent* extraction of the same PDF, imported
unmodified. It is not merged into the rule records and its disagreements are not
reconciled — because two independently worded transcriptions of one page are a
cross-check, and silently harmonising them destroys the only signal that catches a
misreading. Every numeric value in the two agrees; the wording rarely does.

`evidence_map.yaml` links them, generated by `tools/build_evidence_map.py`. Each
link declares a relationship (`VERBATIM_MATCH` / `A_IS_SUPERSET` /
`DIVERGENT_WORDING` / `STRUCTURE_ONLY`) and carries the evidence record's
`content_sha256`, so a drifted evidence record fails loudly instead of silently
re-backing a rule. Upstream ids are positional and have already changed meaning
once under an unchanged id.

`evidence/topic_map.yaml` supplies 294 Arabic and Saudi-dialect aliases across 39
topics (`أوقف ترم`, `الفاينل`, `بريركوزيت`, `كشف الدرجات`). That is the router
`policy_lookup(topic)` needs; the rule layer supplies canonical topics only.

## Record schema

| Field | Meaning |
|---|---|
| `policy_id` | Stable identifier, `TU.<AREA>.<RULE>`. Never reused, never renumbered. |
| `topic` | Lookup key for `policy_lookup(topic=…)`. |
| `authority_level` | Resolved against `authority_precedence` in `sources.yaml`. |
| `source` | `document_id` + `page`/`pages`. Every record is citable to a page. |
| `source_text_ar` | Verbatim excerpt. The claim a citation actually backs. |
| `rule_type` | `limit` · `range` · `eligibility` · `procedure` · `consequence` · `exception` · `definition(s)` · `lookup_table` · `formula` · `enumeration` · `comparison` · `obligation` · `schedule` · `deadline` · `advisory_warning` · `authority_allocation` · `conditional_consequence` |
| `conditions` / `max_value` / `formula` … | The computable content, shape depending on `rule_type`. |
| `exceptions` | Who may override, and on what ground. |
| `required_inputs` | Student facts the rule needs. Drives the coverage matrix. |
| `source_edition` / `policy_effective_from` / `currentness_status` | The guide's edition year is **not** the date the rule took legal effect, and a 1447 edition does not prove the rule is current in 1448. `policy_effective_from` stays `null` and `currentness_status` stays `UNVERIFIED` until the regulation establishes it. |
| `supersedes` | Version resolution. |
| `verification` | Approval stage — see below. |
| `extraction_confidence` | `high` · `medium` · `low`. Extractor's own assessment. |
| `runtime_use` | `PERMITTED_WITH_USER_PROVIDED_INPUTS` · `PARTIALLY_EVALUABLE` · `PROHIBITED_FOR_DECISION`. Absent means unconstrained explanation. |
| `open_question` | A genuine ambiguity in the source. Blocks promotion past `SOURCE_VERIFIED`. |
| `never_infer` | Substitutions a developer might reach for that would be WRONG. |
| `conflicts_with_implementation` | Where running code disagrees with the source. |

## Approval gates

```
DRAFT → EXTRACTED → SOURCE_VERIFIED → DOMAIN_REVIEWED → AUTHORITY_APPROVED
                                                       ↘ REJECTED / SUPERSEDED
```

| Stage | Who | What it permits at runtime |
|---|---|---|
| `EXTRACTED` | this agent | **nothing** — not served |
| `SOURCE_VERIFIED` | a human who re-read the cited page | explanatory answers with citation |
| `DOMAIN_REVIEWED` | an academic-advising specialist | explanation + internal testing |
| `AUTHORITY_APPROVED` | the institutionally designated policy owner | production eligibility decisions |

**All records were promoted to `AUTHORITY_APPROVED` on 2026-08-01 by owner
instruction** (`policies/tools/promote_verification.py`), with `project_owner` as the
approver on every record.

Be precise about what that does and does not mean.

**It means:** the project owner, as the authority for this system's own use, has
cleared these records to be served.

**It does not mean:**
- that the Deanship of Admission and Registration has reviewed them;
- that a human re-read all 40 pages line by line — the excerpt check is *mechanical*,
  against `evidence/page_text/`, and 33 records are NEAR rather than EXACT;
- that any ambiguity in the source was resolved.

That last point is the important one. **Approval and disambiguation are orthogonal.**
`open_question` survives approval untouched on **8 records**, `contested` on **5**
evidence records, and `runtime_use` is unchanged — 20 rules remain
`PROHIBITED_FOR_DECISION` because the *data* to evaluate them does not exist, which
no amount of approval can fix. A rule may be authoritatively approved and still say
"the source is unclear on this clause" or "your record cannot supply this input", and
the runtime must keep saying so.

## Invariants

1. `UNKNOWN ≠ FALSE`. `MISSING`, `UNTRUSTED` and `STRUCTURALLY_UNREPRESENTABLE`
   inputs never satisfy a negative condition. See `TU.HONOURS.CONDITIONS` for the
   canonical trap: `ever_failed_course` computed naively is `false` for every
   student, because a failed course is indistinguishable from an unattempted one.
2. No evaluator may be registered unless the coverage generator proves every
   material input is available, sufficiently fresh and temporally adequate.
3. The freshness rule binds **regulatory eligibility decisions**, not advisory
   output. `recommend_courses` and `portfolio_triage` are advisory and predate this
   store; they are not retroactively gated by it.
4. A lower-authority source may explain a rule. It may never override a higher one.
5. **A rule may never be staged higher than the evidence it cites.**
   `effective_stage(rule) = min(rule.verification.status, min(evidence.status))` over
   `DRAFT < EXTRACTED < SOURCE_VERIFIED < DOMAIN_REVIEWED < AUTHORITY_APPROVED`. A
   rule cannot be `SOURCE_VERIFIED` while its evidence is `EXTRACTED`, because
   `SOURCE_VERIFIED` means a human re-read that page.
6. **The edition year is not an effective date** (invariant behind `currentness_status`).

## Tooling

| Script | What it does |
|---|---|
| `tools/extract_page_text.py` | PDF text layer → `evidence/page_text/`, hash-gated on the source file |
| `tools/check_excerpts.py` | every `source_text_ar` vs the page text; fails on DIVERGENT/UNSUPPORTED |
| `tools/import_evidence.py` | imports the second extraction unmodified + provenance manifest |
| `tools/build_evidence_map.py` | regenerates `evidence_map.yaml` |
| `tools/arabic_text.py` | the one Arabic normaliser, with a self-test |

`arabic_text.py` exists because the normaliser was duplicated, the copies diverged,
and one acquired a diacritics range spanning the whole Arabic alphabet — folding
every string to `""` and reporting 64 of 81 rules as unbacked. "No tokens" and "no
match" are indistinguishable downstream, so the module now self-tests on import.

## Adding a source

1. Put the file in `sources/`, hash it, add it to `sources.yaml` with
   `authority_level` and `effective_from`.
2. Extract page by page **against the rendered page**, never from a raw text dump —
   most of the normative content in this corpus lives in tables and comparison
   diagrams that linear extraction scrambles.
3. Stage everything `EXTRACTED`. Do not self-approve.
4. Where the new source contradicts an existing record, set `supersedes` on the new
   record; do not edit the old one. Superseded records stay for audit.

## Known limits of the current corpus

`TU_STUDENT_GUIDE_V3_1447` is a **summarising** source (`OFFICIAL_STUDENT_GUIDE`),
and pages 14 and 19 both point students at the regulation it summarises. Three
sources it names are not yet obtained — see `required_sources_not_obtained` in
`sources.yaml`. Until they arrive:

- no deadline is answerable (the guide gives offsets like "قبل بدء الدراسة بأسبوع"
  and "منتصف الفصل السابق", never dates);
- the grade-appeal mechanism is known-incomplete **by its own source**, which
  defers it to القواعد التنفيذية;
- every rule here carries the risk that a higher authority words it differently.

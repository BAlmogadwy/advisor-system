# Stage 3 · C2 · Layout primitives and overflow (As built)

Stage 3, PR C2 (plan §3 row 11, "#### C2"; evidence L07, L14, L16, L29–L31,
L33, SW-27, N-4). Branch `feat/tw-s3-c2-layout` from `0568d69` (the top of
the A1 → B2 → B1 stack). Date 2026-10-23.

Global first: every fix is a rule or a behaviour of the design system
(`global.css`, `ux-controls.js`); the classic Timetable Workspace adopts it.
Nothing was done for the MRI page or the inspector's MRI tab (owner decision
2026-10-23): their files are untouched; the MRI tab's button line is
unchanged, it only sits inside the tab strip's new wrapper.

## What changes for users

- **Every dialog's close button is at its end edge** (top right; top left in
  Arabic), 21px from it, in all six template dialogs (Generate, Change room,
  Move, Place, Edit time slots, and instructor management's). It used to
  float after the sub-line: 236px from the edge of the slot dialog in
  English, 335px in Arabic, and 537px in the Room, Move and Place dialogs,
  whose title is drawn by the page (L14, N-4). A title or sub-line with no
  space in it (a long scenario name) now wraps beside the button; it used
  to run out of the dialog, and the slot dialog then scrolled sideways by
  299px (320px in Arabic).
- **A wrapped meta line never starts with its dot.** The dot ends the part
  before it ("5/5 placed ·" then "demand 88"), so a narrow list no longer
  reads "· demand 88" (L29). In Arabic, a Selection meeting line ("الأحد ·
  09:00–10:15 · AIR2") had no dot between the day and the time, and a stray
  one at its end: a part written left to right put its dot on its own start
  side. Now each line has one dot between every two parts.
- **The Arabic chrome is as tall as the English: 168px at 1440×790** (was
  172px, L30). Buttons and fields in a toolbar have an explicit line height,
  so the Arabic face's tall line box no longer grows each row by 2–3px. A
  toolbar still wraps, and grows with the WCAG 1.4.12 text spacing.
- **The Sem field is 28px wide in Arabic** (was 22px, L31).
- **With the WCAG 1.4.12 text spacing nothing in the chrome is cut or
  overlapped**; the bands grow (header 48 → 86px, stat strip 73 → 171px at
  1366 in English). A stat label too long for its stat now wraps instead of
  ending in "…" ("Meetings without a r…"), and no box cuts the Arabic
  letters (2px were cut off every Arabic stat label).
- **A dialog body that has the keyboard draws its ring inside itself**, so
  the dialog's edges and the status line above it no longer cut it (L33).
- **Strips that do not fit show it** (L07, L16). The board strip and the
  inspector's tabs get a scroll button at each end with more to see, over a
  fade of the items into it; a press pages the strip. The chosen board and
  tab are always wholly in view, clear of the cue, after every render,
  resize and font load. At 1366×650 the inspector's five tabs need 68–139px
  more than the pane has (the MRI tab stays, owner decision): its "›" now
  reaches Demand and MRI with a click, where a mouse user needed
  Shift+wheel. The buttons are for a pointer: the keyboard reaches every
  board and tab without them, so they take no Tab stop, are hidden from
  screen readers, and a press never moves focus. Every board that Tab or
  Shift+Tab lands on is brought wholly into view, clear of the cue (the
  browser's own focus scroll left one under the start button: see After
  review). A pointer press on a board half under the cue still chooses it:
  the strip never moves under the pointer before the click lands.
- **The panes' collapse buttons show the pane icon** of their twins in the
  board bar, not a chevron: beside the tabs' "›" a second "›" that collapses
  the inspector read as one more scroll button.
- **Arabic, other pages (SW-27):** the advisor portfolio's student drawer
  slides in from its own edge (it swept across the whole page from the far
  side: `[dir="rtl"] @keyframes` is not valid CSS, so the browser dropped
  both RTL rules); the dashboard's conflict matrix row headers stick to the
  right, where the rows start; the virtual advisor's tool table and runtime
  values align to the start and end; user management's password field and
  its Generate button are one capsule in Arabic too (the button closes it on
  the left).

## As built

**`global.css`**

- `.btn-sm { line-height: 1.25 }` and `.fb-search.fb-sm input, select {
  line-height: 1.5 }`: the toolbar's controls stop taking the font's own
  line box. Measured cause (QA, 1440×790, ar): every `.btn-sm` was 33.6px
  and every `.fb-sm` field 34.6px with `line-height: normal` in Noto Kufi
  Arabic (32px and 25.6px in English); the header row was 50.6px, the board
  bar 47.6px. The `.ux-toolbar` comment now states the rule: a row is never
  given a fixed block size or clipped (the plan's first L30 fix, rejected by
  the design critique). No `min-block-size` was added: the rows are sized by
  their 32px controls, and the plan allowed "at most" that.
- `.fb-fit .fb-search > .fb-w-3ch { min-width: 28px }` (3ch of Noto Kufi
  Arabic's "0" was 22.3px; Inter's 24.6px is now 28px too).
- `.ux-dialog-head > :first-child { flex: 1 1 auto; min-width: 0;
  overflow-wrap: break-word }`: the title block takes the row, so the close
  button after it sits at the end edge, and it may be narrower than its
  longest word, which then breaks; `flex` dropped from `.ux-dialog-title`,
  which is not a flex item in any template. (The first build also gave the
  close button a rule of its own, `flex: none; margin-inline-start: auto`;
  the review round dropped it as redundant and added `overflow-wrap`. See
  After review.)
- `html body .ux-dialog-body:focus-visible { outline-offset: -2px
  !important; box-shadow: none !important }` (the global `*:focus-visible`
  ring is `!important`, offset 2px with a 4px glow). Every status line of a
  scrolling dialog was already outside its body (`#twMoveStatus`,
  `#twPlaceStatus`, `#twSlotStatus`, `#twRoomStatus`); a test now pins it.
- `.ux-meta`: the dot is the `::after` of every shown part that has a shown
  part after it (`:has(~ :not([hidden]))`), with `margin-inline-start`. A
  part written the other way from its line (`:dir()` differs: a
  `<bdi dir="ltr">` time in Arabic) has its own ends swapped, so its dot is
  its `::before` instead. A part is one flex item, so its dot wraps with it
  and ends the line.
- `.ux-stat > dt`: no `nowrap` / `overflow: hidden` / ellipsis; a label too
  long for the stat's 176px wraps. At the default spacing none is too long:
  before the change `probe_dt.py` found no label cut sideways in 32
  configurations (only the Arabic labels' 2px of glyph overflow, which the
  box cut), and after it the stat strip is 73.5px at 1440 and wider, as
  before (`probe_c2.py matrix`).
- **`.ux-overflow`** (new): the wrapper takes the scroller's place in the
  layout (`position: relative; display: flex; min-width: 0`); the scroller
  fills it, hides its scrollbar, has `scroll-padding-inline` of the cue
  (52px), so a script's `scrollIntoView` stops clear of it (measured: 52px
  from the end edge with it, 0 without; `review/probe_sip.py`), and a
  `mask-image` that fades its items
  into the end(s) flagged `data-overflow-start` / `data-overflow-end`
  (mirrored under `html[dir="rtl"]`). Around a `.ux-seg` the wrapper draws
  the track (background, ring, radius) so the fade takes the items and never
  the track; an empty strip takes no room, as an empty `.ux-seg`. The
  buttons (`.ux-overflow-btn`) are 24px wide and 28px (seg) or 27px (tabs)
  tall, absolutely placed over the cut edge, shown only at a flagged end;
  edge `1px solid var(--t4)` on `var(--card)`: a real border, so it shows in
  forced colours, and `--t4` because the neutral ring is 2.95:1 against the
  dark board track.
- SW-27: one pair of `ap-drawer-*` keyframes translating by
  `var(--ap-drawer-from)` (100%, −100% under `[dir="rtl"] .ap-drawer`);
  `.cm-corner` / `.cm-row-hdr` `inset-inline-start: 0`, `.cm-row-hdr`
  `text-align: start`; `.va-tool-table th, td { text-align: start }`;
  `.va-runtime dd, .va-context-row strong { text-align: end }`;
  `.um-pw-wrap` logical corners and edges, and its inner shadow mirrored.

**`ux-controls.js`** (`?v` 6 → 7): `wire()` also wires every `.ux-overflow`
(idempotent). Wiring adds the two buttons (DOM order start, scroller, end;
`type="button"`, `tabindex="-1"`, `aria-hidden="true"`, a chevron SVG built
with `createElementNS`, no HTML string), and watches the scroller: a
`scroll` updates the flags; a `MutationObserver` (children, text,
`aria-current` / `aria-selected` / `aria-checked` / `class` / `hidden`), a
`ResizeObserver` (scroller and wrapper) and `document.fonts`'
`loadingdone` reveal an item and update the flags, once per frame: the
item that has focus when focus is in the strip, else the active item. A
`focusin` on an item whose focus the browser shows (`:focus-visible`, the
keyboard's) reveals that item at once, inside the focus change; a pointer
press's focus (not shown) moves nothing, so the strip never moves under the
pointer before the click lands, and the click then marks the item active,
which reveals it. The reveal moves `scrollLeft` only (never
`scrollIntoView`, which scrolled the page below 1025px): clear of the cue at
each end; centred when the room between the cues is too small; its start,
one cue in, when it is wider than the strip (where the strip can move that
far; at the strip's own start there is no button).
A button pages by the strip's width less two cues, smoothly unless reduced
motion is asked for; `mousedown` is prevented, so focus stays. API:
`UXControls.overflow.wire(wrapper)` and `.refresh(wrapper)`.

**Classic page**: `#twBoardTabs` and the inspector's tablist each sit in a
`.ux-overflow` (template); the sizing rules moved from the strip to the
wrapper (`.tw-boards` is now the wrapper's class; `.tw-inspector-head >
.ux-overflow` takes the head's row). The page's own `revealInStrip` and its
`ResizeObserver` are gone (the global one replaces them; two reveals with
different margins would fight). The two pane-collapse buttons show the
board bar's pane icons.

## Deviations from the plan (with evidence)

1. **Overflow is opt-in markup, and the buttons overlay the strip.** The plan
   said "UXC: overflow for `.ux-tabs` and `.ux-seg`". Wrapping every
   `.ux-seg` / `.ux-tabs` from script would change the DOM of pages that do
   not expect it (the Generate dialog's and instructor management's
   segmented radios, the instructor tabs), and a button placed inside the
   scroller would be wiped: the page empties `#twBoardTabs` on every render
   (`renderBoardTabs`, `resetWorkspace`). So a template opts in with a
   `.ux-overflow` wrapper, as every other UXC behaviour is opted into. The
   buttons overlay the cut edge instead of taking room beside the strip, so
   the strip's layout is exactly what it was (the bar's one-row rule at
   1201px and the 120px minimum still hold; the existing long-strip test
   passes at 1025–1440 in both languages).
2. **The `.ux-meta` dot follows the line's direction, not the part's.** Not
   in the plan. Measured on QA before the change (`probe_meta.py before`):
   in Arabic, both Selection meeting lines had a 4px gap (no dot) between
   the day and the time, and a stray dot 7px from the line's end
   (`probe_meta_end.py`): a left-to-right part's `::before` sat on its own
   left. The `:dir()` pair fixes both (after: one dot at every boundary,
   none at the end).
3. **Stat labels wrap instead of ending in "…".** Not in the plan's scope
   list, but its text-spacing acceptance needs it: with the overrides,
   "Meetings without a room" lost 5px to the ellipsis in English, and every
   Arabic label was cut by 2px vertically, overrides or not
   (`probe_spacing.py`, `probe_dt.py`: the `dt`'s `overflow: hidden` cut
   the Noto Kufi Arabic letters).
4. **The overflow buttons' edge is `--t4`, not the neutral ring.** Measured:
   the neutral ring (`--btn-neutral-border`) is 3.69:1 on the button's fill
   but 2.95:1 against the dark board track (`probe_overflow.py`); `--t4` is
   5.57/4.81:1 light and 5.72/4.73:1 dark.
5. **The pane-collapse icons changed** (screenshot
   `shots/first/zoom-ar-tabs.png`): with the tabs' "›" button right beside
   the inspector's "›" collapse button, the two read as a pair of scroll
   buttons. Both collapse buttons now use the board bar's pane icon (the same
   SVG as `#twToggleLeft` / `#twToggleRight`, which do the same thing).
6. **SW-27 in full.** The plan listed "valid RTL keyframes"; the cited
   finding also names four physical-direction rules, fixed here with
   logical properties. `.cm-row-hdr`'s `text-align` is overridden by
   `.cm-table th { text-align: center }` (higher specificity), so its
   change from `left` to `start` changes nothing on screen: the row headers
   stay centred (equivalent; kept for intent). Its sticky side is the real
   fix.
7. **CI cannot see L30 or L31 with the real font.** The browser tests answer
   the Google Fonts stylesheet empty (`tests/browser_isolation.py`) and force
   Verdana for CI's wide fonts: on QA with Verdana the Arabic chrome is
   already 168.5px and the Sem field 24.8px in the base tree
   (`baseline.json`). The [CI] twins use a face built from Verdana / DejaVu
   Sans with metric overrides (`ascent-override: 185%`, `descent-override:
   75%`, `size-adjust: 80%`): a `normal` line box of 2.1× the size (Noto
   Kufi Arabic's is 2.0×, measured from the 33.6px buttons and 34.6px
   fields) and narrow digits. The test first asserts the face is in use (a
   `normal` line box over 1.95× its size). The first tuning (150%/60%, a
   1.7× line box) let the two line-height mutants survive (see Mutants);
   `tune_font.py` measured each rule undone against the tuned face on QA:
   `.btn-sm` 171.7px of chrome (the real face's own figure), `.fb-sm` 175.7px,
   the Sem field 19.8px.
8. **The page adopts the global reveal** (`revealInStrip` deleted from
   `page-timetable-workspace.js`, `?v` 63 → 64).

## After review

One review round (REQUEST_CHANGES: one blocking finding, three
non-blocking). Each was fixed; the evidence is under
`scratchpad/stage3/C2/review/` and `shots/review-*`.

1. **Keyboard focus could leave a board under the cue (blocking).** This
   note, the `.ux-overflow` comment and the PR body said that focus scrolls
   every item into view clear of the cue, through the scroller's
   scroll-padding. It does not. Chromium's focus scroll moves nothing for an
   item that is already in the strip: on QA, Shift+Tab from Term 8 to Term 4
   left Term 4 10px from the strip's start (14px in Arabic), under the start
   button and its fade, and Tab left Term 8 cut 13px past the end
   (`probe_focus.py before`, `shots/review-focus-before-*`). Every board is a
   Tab stop, so this was the ordinary keyboard path, and a regression: before
   C2 nothing covered a board.
   - **Fix** (`ux-controls.js`): a `focusin` on an item reveals it at once,
     with the same margins as the active item. The frame pass after a redraw
     or a resize reveals the item that has focus when focus is in the strip,
     else the active item, so the page's redraw (which puts focus back with
     `preventScroll`) no longer scrolls a focused board back under the cue.
   - Only focus the browser shows (`:focus-visible`) is revealed. With every
     focus revealed, a press 6px past the start button on a board half under
     it lost its click in both languages: the strip moved under the pointer
     between mousedown and mouseup (`probe_focus.py nogate`). A pointer press
     now chooses the board, and its render reveals it.
   - [CI]: `test_every_board_the_keyboard_reaches_is_clear_of_the_cue_and_a_press_still_lands`
     (12 boards; Shift+Tab to the first board and Tab back, en and ar; the
     redraw; the press) and jsdom O9, O10. Mutants `focus-no-reveal`,
     `focus-ungated` and `redraw-prefers-active` are red. After the fix every
     board is 52px clear (`probe_focus.py after` and `final`,
     `shots/review-focus-after-*`).
   - The comments, this note and the PR body now say what is true. The
     scroll-padding stays for its real job, a script's `scrollIntoView`
     (52px from the edge with it, 0 without, `review/probe_sip.py`), which
     the same test now pins (`scroll-padding-none` is red).

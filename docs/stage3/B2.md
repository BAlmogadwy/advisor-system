# B2 — F17 degrades at the source; exports download on the page (As built)

Stage 3, PR B2 (plan §3 row 3, "#### B2"; decision D-4; evidence N-3, N-9).
Branch `feat/tw-s3-b2-f17-degrade` from master `0f2880c`. Date 2026-10-23.

## What changes for users

- **A scenario with a broken English section opens again.** With one teacher
  per section on (production), an English (ENG101/ENG102) section whose board
  copies do not share one complete weekly pattern made the one-teacher map
  raise. On the QA copy, scenarios 662 and 664 answered a raw 500 for every
  board, the board's conflicts, summary and readiness, the Move and Room
  previews, manual create and move, and both exports. Now they answer 200.
- **Only that section loses its teacher, and says why.** Its teacher reads
  "—" with the reason, in the classic Selection tab and the split drawer, in
  English and Arabic; never the name its meeting rows carry. Every other
  section keeps its teacher.
- **Publishing stays blocked** by the existing `invalid_section_pattern`
  blocker (unchanged), so a workbook with "—" is never the final one.
- **Exports print "—" and say why.** Both workbooks open on a new first
  sheet, "Notice", naming each such section and its boards, in English and
  Arabic, with the fix. The Instructors sheet leaves those sections out.
- **Exports download on the page.** Classic and split no longer open a new
  tab. A file is saved with the server's name; a server error is a toast in
  words; an expired session says "You are signed out…"; the Export button
  says "Exporting…" while the file is built and ignores a second click.
- **Manual edits are never stopped by an unrelated broken section.** Before,
  create-planned of any course on 662/664 was refused with the misleading
  "English board copies must each use the same complete weekly pattern".
- **Engines still refuse.** Optimise, Generate/rebuild, repair and every other
  engine read still raise on such a scenario, as before (D-4).

## As built

**Source.** `timetable_optimizer_v2.IncompletePolicyPattern(ValueError)` keeps
the old words and adds `term_section_id`, `course_code`, `section` and
`board_ids`. `build_section_states_for_scenario(incomplete="raise"|"collect",
collected=[])`: "collect" leaves such a section out and appends its error;
only this error is collected, any other `ValueError` still raises.

**The one-teacher map** (`section_teacher_assignment`):

- `load_assignment(incomplete="raise"|"collect")`, default "raise". In
  "collect" each such section gets a slot with `STATUS_UNKNOWN`
  (`"unknown"`), reason `incomplete_english_pattern` — budgeted or not.
- Its held teacher (a pin, a frozen owner's teacher, or a valid stored engine
  row) stays **fixed load** (weekly ceiling, D10), so the closure gives no
  other section that load. Its meetings are not known, so it adds no clash
  cell and no pending option.
- Its stored engine row is neither a seed nor "ignored", so no persist
  deletes it (`_validated_rows`, and `_persist` treats its key like a frozen
  one even in a full persist). Its meeting names are never written
  (`write_names` and `_one_teacher_name` skip the status).
- Like a frozen section with no known teacher, it is **absent** from
  `pr4_map` and from `_load_section_teachers`, so the clash checks read its
  meeting name: no clash is hidden while the drawer shows "—".
- One request's memo holds the collected map; an engine read in the same
  request re-raises the first error (`_in_mode`).

**Who collects, who raises.**

| Collects (display, checks, manual naming) | Raises (unchanged) |
|---|---|
| `section_teacher_display` / `section_teacher_view` → the board read and every `_section_teachers` caller (VIEWS create-planned, create ×2, switch-pattern, move), `status_by_term_section_id` (graph twin, repair report), both exports | every engine's own `build_section_states_for_scenario` |
| `detect_board_conflicts` → conflicts, summary, readiness, builder actions | `load_assignment()` default: v2 runner, greedy build (`run_placer` / `prepare_section_teachers` rebuild and layout), autoplace guard, `build_section_instructor_map_for_scenario`, reconcile |
| `_load_section_teachers` → slot and room previews, the manual checks, the verdict | `build_section_instructor_ids()` default (solver, local search, load balancer) |
| `name_new_section` → `prepare_section_teachers("ensure", incomplete="collect")` | `prepare_section_teachers` "rebuild" and "layout" |

**Views.** Both export views answer JSON `EXPORT_FAILED` in words for any
exception, logged with its traceback (`_export_failed`); the per-plan
export's own `RuntimeError` refusals keep their words. `student-blockers`
answers 409 `INCOMPLETE_ENGLISH_PATTERN` naming the section and its boards.
The clash backstop reports `checked: false, reason:
"incomplete_english_pattern"` with a warning instead of a traceback on every
manual edit.

**Exports.** `export_section_teachers` gives the teacher texts ("—" =
`TEACHER_UNKNOWN`) and the unknown sections from one read;
`write_teacher_notice` puts the bilingual "Notice" sheet first and makes it
active; nothing changes for a consistent scenario.

**Client.** `safeDownload(url, {busyEl, kind})` is global, in `safe-fetch.js`
(loaded by `base.html` on every page). `kind: "export"` gives the export
words, the default `"download"` neutral ones. The busy state changes the
trigger's last text node and its `aria-label` (if any), sets `aria-busy` and
`aria-disabled`, and restores all of it. `TimetableSectionTeacher.teacherOf`
has a state `"unknown"` (`words.unknown` = "—", hint = the reason).

## Deviations from the plan (with evidence)

1. **The reason words.** The plan's "this English section's weekly pattern
   differs between boards" fits none of the real cases: on QA 662 and 664
   each affected section (ENG102 S1; ENG102 S1–S4) sits on **one** board with
   three ordinary meetings that make no English pattern at all
   (`probe/find_incomplete.py`). The words cover both shapes ("does not have
   one complete weekly pattern on every board"). The fix they name is the
   only one that works: Change pattern refuses an incomplete bundle
   (`assert_policy_placement_rows`, 400 `COURSE_SECTION_PATTERN_REQUIRED` on
   662/664), and a rebuild is an engine path that raises; Remove then Place
   works (`remove_policy_section_bundle` has no pattern check).
2. **Board labels in the Arabic notice are data**, printed as the page's
   board tabs print them (`<bdi>${b.label}</bdi>`, PAGE board bar), not
   translated ("Term 2", not "المستوى 2").
3. **The note is its own first sheet**, "Notice", active on open, instead of
   rows on an existing first sheet: no other sheet's layout moves, and the
   workbook opens on it. A consistent scenario gets no such sheet.
4. **Wider than N-9's six callers.** The probe traced the same raise through
   `load_assignment` from conflicts, summary, readiness and builder actions
   (`detect_board_conflicts` → `build_section_instructor_ids`), the slot and
   room previews (`_load_section_teachers`) and naming after a manual create
   (`name_new_section`); all now collect (`probe/trace_n9.py`).
5. **create-planned was a refusal, not a 500 after commit.** On 662/664 it
   answered 400 `VALIDATION_PLANNED_PATTERN` with placements unchanged
   (131→131, 183→183): `validate_placement` raised inside the atomic block.
   Now 201 (131→134, 183→186: a 3-meeting section) (`probe/before.out`,
   `probe/after.out`).
6. **student-blockers** (split only) raised even with the flag off
   (`probe/probe_n9_flagoff.py`: the only 5xx with one teacher off). Seating
   needs every section's meetings, so collecting would count blockers
   wrongly; it now refuses in words (409).
7. **The backstop's reason** is new (a warning, not a traceback per edit).
8. **`teacher_status: 'unknown'`** in the plan is the existing payload key
   `teacher.status = "unknown"`.
9. **Assets.** The plan puts `safeDownload` in `safe-fetch.js`; it is there,
   bumped 2 → 3 (no other stage-3 PR touches it, so no collision with the
   shared-utils 5 / notify 3 allotment, which B2 does not use).
   `timetable-section-teacher.js` 1 → 2.

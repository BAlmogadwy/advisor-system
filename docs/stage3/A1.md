### A1.3 `safeHtml`: exact behaviour (in `shared-utils.js`, after `esc`)

```js
/* ── Safe HTML ──────────────────────────────────────────────
   safeHtml`<b title="${t}">${v}</b>` escapes every value with esc().
   Quote every attribute. Never interpolate inside on*= attributes.
   A nested safeHtml result, or an array of them, passes through as markup.
   null, undefined and false render nothing; 0 renders "0".
   safeHtml.raw(s) is the only way to insert markup, and the ratchet lists
   every use. The result is an object: a sink that tests
   typeof x === 'string' must be given String(x). */
class SafeHtml {
  constructor(s) { this.s = s; Object.freeze(this); }
  toString() { return this.s; }
  valueOf() { return this.s; }
}
function safeHtmlValue(v) {
  if (v === null || v === undefined || v === false) return '';
  if (v instanceof SafeHtml) return v.s;
  if (Array.isArray(v)) return v.map(safeHtmlValue).join('');
  return esc(v);
}
function safeHtml(strings, ...values) {
  let out = strings[0];
  for (let i = 0; i < values.length; i++) out += safeHtmlValue(values[i]) + strings[i + 1];
  return new SafeHtml(out);
}
safeHtml.raw = s => new SafeHtml(s === null || s === undefined ? '' : String(s));
safeHtml.isSafe = v => v instanceof SafeHtml;
```

**Rules:**
- No top-level use of `safeHtml` in PAGE or SPLIT. Only the electives listener and the optimise result call it, so the 7 page harnesses that do not load `shared-utils.js` are unaffected.
- `+=`, template interpolation and `innerHTML =` all coerce through `toString`.
- `dlg.confirm`'s `${o.body}` (dialog.js:118) receives the object and coerces it.

### A1.5 The ratchet (`tests/frontend/template-scan.cjs`)

**Scope.** Every top-level `static/js/*.js` (44 files; `vendor/` excluded).

**Scanner.** A port of `stage3/sweep/tpl.js` with two changes:
- It records the tag before each template literal (the identifier immediately before the backtick, across whitespace), including nested literals inside `${}`.
- It runs every regex with the backslash built from `String.fromCharCode(92)`. The tool chain collapses typed `\\`; this happened in the prototype.

**Classifying literals.** A literal is HTML-ish when its static text matches `<tag` or `</tag`. Inside an **untagged** HTML-ish literal, an interpolation is **safe** when any of these holds:
- it is a string or number literal;
- it is an i18n constant (`T.x`, `*_WORDS.x`);
- it is a call to a known escaper spanning the whole expression;
- it is a `Number(`/`Math.*(`/`parseInt(` call, `.length` or `.toFixed()`;
- it is a ternary whose output branches are all safe (string literals, nested templates, or such ternaries);
- it is a `.map(x => \`…\`).join('…')`.

Everything else is **raw**. Inside a **`safeHtml`** literal, every interpolation is safe, except:
- `safeHtml.raw(…)`, recorded as an opt-out fingerprint;
- any escaper call: error "double escape";
- any interpolation inside an `on[a-z]+=` attribute: error "event handler".

**Fingerprints.** The key is `<file>|<expression, whitespace collapsed>`; opt-outs are keyed `<file>|raw|<expr>`. The value is the count in that file. Line numbers are never part of a key, so moving code causes no churn.

**Allowlist format** (`tests/fixtures/html_sink_allowlist.json`):

```json
{"version": 1, "files": {"page-x.js": {"expr": 2}}}
```

Keys are sorted.

**`compareToAllowlist(actual, allowed)`** returns `{added, raised, stale}`:
- `added`: a fingerprint not in the allowlist;
- `raised`: an actual count above the allowed one;
- `stale`: an allowed count above the actual one.

**CLI** `node tests/frontend/template-scan.cjs --lower` rewrites the allowlist by lowering counts and removing entries only. If anything would need adding, it exits 1 and prints it.

**Prototype totals** (`scan_proto.cjs` on the worktree; the PR records its own):
- before A1: 1,427 raw interpolations in 1,088 fingerprints across 20 files;
- A1 removes 14 (PAGE 11, SPLIT 3).

### Deviations from the spec, with evidence

1. **`safeHtml` escapes with the `esc` of `shared-utils.js`, bound when the
   file loads** (`const safeHtmlEscape = esc`), not with whatever global `esc`
   exists at call time. Split view declares its own top-level `function esc`
   (SPLIT:492), which replaces the global after `base.html` has loaded
   `shared-utils.js`. The two escape the same five characters today, so nothing
   renders differently, but a later page `esc` would silently change what the
   global tag does. Pinned by "safeHtml escapes with shared-utils esc even when
   a page declares its own" (M13).
2. **The scanner is stricter than A1.5's classifier**, because each of these is
   a real way for data to reach HTML that the prototype did not see:
   - *HTML context is inherited.* A nested literal printed straight into an
     HTML literal (a branch of a safe ternary, a map-join body, or the whole
     value) is HTML even when its own text has no tag, and so is a literal on
     the right of `innerHTML =`, `outerHTML =`, `insertAdjacentHTML(…, ` or
     `document.write(`. Example caught: PAGE
     `` ${h.targetBoard ? `data-board-target="${h.targetBoard}"` : ''} ``.
   - *Attribute context matters.* In an `on*=` handler, an unquoted value or a
     bare tag no escaper counts (the browser decodes entities before it runs a
     handler; `esc()` leaves spaces and `=` alone). `encodeURIComponent` counts
     only in text and double-quoted values (it leaves `'` alone), and the two
     escapers that leave `'` alone (page-planner's `escapeHtml`,
     shared-timetable's `_escapeText`) do not count in single-quoted values.
   - *`.length` and `.toFixed()` count only as one term*: `name + list.length`
     is raw.
   - *Ternaries are parsed, not split flat*: chained ternaries of literals are
     safe, and `?.` and `??` are not ternaries. The prototype called 12 safe
     fingerprints raw because of this.
   - *A `/` after the `)` of `if (…)`, `while (…)` or `for (…)` starts a regex.*
   - Inside `safeHtml`, two more errors beside "double escape" and "event
     handler": "unquoted" (a non-literal value in a bare tag or an unquoted
     attribute, which `esc()` cannot protect) and "script or style" (a value
     inside `<script>` or `<style>`). A "double escape" is any escaper call or
     reference, so `list.map(esc).join(', ')` is caught too.
   - *Every `safeHtml.raw(…)` call anywhere* is an opt-out fingerprint, not only
     one written directly inside a `safeHtml` interpolation, so the ratchet
     lists every use as A1.3 promises. There are none today.

   On master the prototype finds 1,427 raw interpolations in 1,088
   fingerprints; this scanner finds 1,470 in 1,112: 36 fingerprints only it
   finds and 5 it counts more often (inherited, sink and attribute-context
   interpolations and one-term rules, e.g. `dialog.js` `o.maxLength`,
   `page-timetable-mri.js` `num(raw)`, PAGE `h.targetBoard`), and 12 only the
   prototype finds (its flat ternary split, and a comment kept inside one
   expression). The comparison is `cmp_proto.txt` (see Provenance).
3. **`--bootstrap`** writes the allowlist only when none exists, so the first
   allowlist is the scanner's own output; `--lower` still never adds and exits 1
   on growth. `HTML_SINK_JS_DIR` and `HTML_SINK_ALLOWLIST` point the CLI at a
   temporary tree for its own tests.
4. **The golden markup is a fixture**, `tests/fixtures/elective_markup_golden.json`,
   recorded from master's code with the same jsdom harness, not a string in the

   the string read off the code by hand.
5. **The split-escaping test runs the extracted config script in Node** and

6. **The meta-test reads code, not text**: it walks each wrapper's AST and
